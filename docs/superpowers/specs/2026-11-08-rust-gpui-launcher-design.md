# AProgram Rust 与 GPUI 重构设计

## 目标

AProgram 用于在同一台 Windows 电脑上快速切换办公、游戏等软件组合。首版交付 Windows x64 桌面应用。用户可从系统托盘直接切组，也可快速恢复主窗口编辑配置。资源优化以托盘常驻为重点，窗口恢复和切组响应优先。

## 使用流程

- 托盘左键显示或激活现有窗口。开启「关闭窗口时收到托盘」时，关闭按钮隐藏窗口，保留选中组、窗口大小和位置。关闭该设置时，关闭按钮退出 AProgram。
- 托盘右键菜单列出软件组，并标记当前环境。点击组名立即反馈并执行差量切换。主窗口里的「切换到此组」与托盘调用同一逻辑。单击主窗口的组名只浏览该组。
- 保留新建、复制、重命名和删除软件组，拖入 `.exe` 或 `.lnk`，单击应用卡片切换启用，双击单独启动，以及一键启动组和关闭组。应用卡片分别显示「是否参与组操作」和「是否正在运行」。
- 切组进行时，界面仍可操作和隐藏，托盘与窗口的批量命令显示正在处理并暂时禁用。退出 AProgram 等待这次操作结束或超时后完成。启用开机自启时，登录后直接进入托盘，并在同一进程中准备可恢复的主窗口。

## 架构

单个 Rust 可执行文件、单个实例。以固定版本的上游 GPUI 创建主窗口，通过 Windows 后端使用 DirectX 11 和 DirectWrite。托盘由 Win32 通知区域 API 注册，Explorer 重启后重新注册。主窗口和托盘共享同一份 Rust 状态。图标按需提取并复用，同一进程内切组或恢复窗口时复用已加载的图标。[GPUI](https://github.com/zed-industries/zed/tree/main/crates/gpui) · [Zed Windows 渲染](https://zed.dev/blog/zed-for-windows-is-here) · [Windows 通知区域 API](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shell_notifyiconw)

GPUI 线程只负责交互和呈现。后台任务负责提取图标、扫描进程、启动和关闭应用，结果回到共享状态。窗口可见时最多每 2 秒发起一次周期扫描，卡片复用同一份结果。打开窗口、执行组操作或收到操作结果时合并刷新请求。窗口隐藏时停掉周期任务，切组等命令按需获取快照。

保留 GPUI 窗口意味着渲染设备和缓存可能常驻。以实测的线程唤醒、CPU、GPU 和内存区分 GPUI 后端开销与应用自身开销。隐藏时应用停止主动提交重绘请求，验证窗口恢复速度后再调整渲染空闲行为。[GPUI Windows 后端](https://github.com/zed-industries/zed/blob/main/crates/gpui_windows/src/platform.rs)

## 切组和进程管理

「当前环境」表示最近一次切换到的软件组，批量启动和关闭命令各自操作指定组。切换开始后显示「正在切换到 X」，操作完成后显示目标组和结果。有部分失败时显示待处理应用，区分环境选择和进程实际状态。首次选择环境时只启动目标组启用且未运行的应用。后续切换按上次切换时记录的启用路径和目标组配置计算差异，以同一份进程快照判断运行状态。

| 对比当前组与目标组的启用应用 | 操作 |
| --- | --- |
| 两组共用 | 保留其当前运行状态 |
| 仅当前组启用且正在运行 | 发出关闭请求 |
| 仅目标组启用且尚未运行 | 发出启动请求 |

先集中发出关闭请求，随即启动目标组应用，后台统一跟踪关闭结果。关闭等待共用一个有界时限，首版设为 3 秒。应用弹出保存对话框或超时且进程仍在时，显示仍在运行。权限不足时显示操作失败和已知的进程状态。再次选择同一环境时，应用配置差异并重试仍符合当前配置的失败项。切换到其他环境时，先前关闭失败的应用也参与判断，目标组需要的应用继续保留。单独的「关闭组」保留确认流程。

Windows 启动层通过 Shell 打开原始 `.lnk`，保留快捷方式的参数和工作目录。识别进程时使用解析后的可执行文件完整路径。发出关闭前用进程句柄核对身份，避免 PID 复用和同名应用误关。关闭首先发送 `WM_CLOSE`，需要强制结束时提供独立确认。失效路径、快捷方式解析失败、无法查询的进程及退出超时均按条目反馈，其他应用继续处理。[ShellExecuteExW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecuteexw) · [进程映像完整路径](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew) · [WM_CLOSE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-close)

## 本地配置

- 新版状态文件位于 `%LOCALAPPDATA%\AProgram\state.json`。同一个文件保存软件组、应用启用状态、当前环境及上次切换结果、设置和窗口状态。单个写入者通过同目录临时文件完成原子替换。加载失败时展示可恢复错误，原文件保留以供恢复。
- 首次启动时，发现同目录有 `software_groups.json` 则提供导入，也支持选择旧版目录。兼容纯路径数组和包含 `path`、`enabled` 的条目数组，纯路径默认启用。相对路径以原配置所在目录为基准。存在 `settings.json` 时一并读取开机自启和关闭到托盘偏好。两份旧文件只读，新版导入失败时保留当前状态。
- 保留当前用户范围内的开机自启设置。导入自启偏好后，在用户通过新版设置启用自启时更新 Windows 注册表。

## 验收

先用 GPUI 与 Win32 托盘验证同一窗口的隐藏、恢复和托盘菜单操作，再实现业务迁移。自动验证组差量、已运行的目标应用、同路径的快捷方式别名、旧格式导入、损坏配置和失败项重试。Windows 实机使用可控的测试程序覆盖保存提示、关闭超时、重复点击、切换中隐藏、同名不同路径、托盘图标恢复与自启。

使用同一台 Windows 11、20 个测试条目和 Release 构建评估性能。分别记录窗口打开和隐藏的 CPU 时间、工作集、私有提交内存、GPU 活动和进程扫描次数。已采集的旧版单次基线是打开窗口时 72.0 MiB 工作集、75.5 ms/s CPU，隐藏时 74.6 MiB 工作集、69.0 ms/s CPU，两种状态各 12 秒、各扫描 120 次。正式对比重新采样旧版和新版。

| 指标 | 首轮目标 | 采样方式 |
| --- | --- | --- |
| 托盘选组到开始执行 | p95 ≤ 100 ms | 30 次切换，测命令接收至发出首个关闭或启动请求。无差异时测至操作结果返回 |
| 托盘点击到主窗口可交互 | p95 ≤ 150 ms | 30 次已初始化窗口的隐藏与恢复，测点击至首帧显示且可处理输入 |
| 隐藏后的后台进程扫描 | 0 次 | 稳定后静置 60 秒，记录扫描计数。执行组操作时单独记录 |
| 隐藏后的 CPU 时间 | 低于同条件旧版 | 稳定后静置 60 秒，至少采样三轮，记录 CPU 时间增量并除以采样时长 |

切组耗时与目标软件自身的启动、退出时间分别记录。工作集、私有提交内存和 GPU 活动随首轮数据一并报告，作为后续优化的依据。
